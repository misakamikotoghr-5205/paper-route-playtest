# 相近作品与开源比较

核验 2026-11-05。本项目不是「全球首创」：网格解谜、取送路线、撤销、自动求解与规则测试都已有成熟先例。本作的组合目标是把一个可玩的四关取送谜题，与可读的动作证据、严格重放和错误投递反例放在同一份轻量离线交付中。

| 相近主源                                                  | 阅读与许可                                                                                                                                                                                                          | 已有价值                                                   | 本作差异与不足                                                                                                                                   |
| --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| [PuzzleScript](https://github.com/increpare/PuzzleScript) | 阅读README及[MIT许可](https://github.com/increpare/PuzzleScript/blob/421328df500fc05ba35c1b4a8ccc32c82328ede5/LICENSE)；核验HEAD `421328df500fc05ba35c1b4a8ccc32c82328ede5`                                         | 成熟的HTML5谜题引擎、规则语言与创作生态，远比本项目通用。  | 本作不是引擎或编辑器；只有四关，采用单件容量、门牌匹配、桥开关和返程预算，并把「为何失败」变成可下载反例。没有复用PuzzleScript关卡、代码或视觉。 |
| [PathFinding.js](https://github.com/qiao/PathFinding.js)  | 阅读README、package元数据及README末尾MIT全文；核验HEAD `2904a9afba483c02b5a61eb60fefd63e9b2db78c`，[README固定版本](https://github.com/qiao/PathFinding.js/blob/2904a9afba483c02b5a61eb60fefd63e9b2db78c/README.md) | 面向二维网格游戏的多种寻路算法，带算法可视化与最短路说明。 | 本作不只搜索坐标，还在状态中保留携带包裹、已送达集合、桥状态；同一坐标在不同任务状态下不能合并。规模小，BFS足够；没有其丰富算法或性能优化。      |

借鉴方式：参考两者的可表达规则、网格路径和可观察执行的设计方向；BFS为通用算法，本实现从头编写。没有安装、复制、修改或捆绑上述仓库代码；因此没有把第三方许可冒充项目原创代码的许可，也没有假称「实际集成」它们。若后续复用源码，需连同对应许可和版权标识保留。

本次实质实现：独立的纯状态引擎与严格动作重放；从任意当前合法状态求剩余最短路线；容量/门牌/桥状态参与搜索去重；规划与执行每步经过同一合法性检查；隔离的人工注入缺陷通过搜索得到最短反例，输出初态、种子、动作、不变量与前后差异。用户可以把无法完成的路线交给别人复现，而不是只分享一张结果截图。

验证：`npm test`覆盖16个关卡/变体组合的通关及15类核心回归；含投递门牌边界、容量、桥状态、预算、终局、撤销、防伪成绩和可重现缺陷。BFS最多检查30000状态；达到上限明确返回limit。种子只做四种镜像，不用于夸大内容数量。没有用户测试或实际赛事成绩，尚不能证明商业价值或相对成熟引擎的性能优势。
